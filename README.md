# STP (Spanning Tree Protocol) и проблема L2-петли

## 1. Что такое L2-петля?

Для начала разберёмся, что такое L2-петля.

L2-петля — это проблема, возникающая на канальном уровне модели OSI (Layer 2).

Когда мы соединяем несколько коммутаторов, они работают корректно. Но если для отказоустойчивости мы создаём между ними резервные физические соединения, может возникнуть проблема — **L2 Loop (петля второго уровня)**.

## 2. Как возникает L2-петля?

Представим, что у нас есть три коммутатора, соединённые между собой в форме треугольника. STP при этом отключён.

1. ПК отправляет широковещательный кадр (Broadcast).
2. Первый коммутатор получает кадр и отправляет его через все порты, кроме того, через который кадр поступил.
3. Второй коммутатор получает этот кадр и также рассылает его через остальные порты.
4. Третий коммутатор делает то же самое.
5. В результате кадр снова возвращается к первому коммутатору через другой порт.

Поскольку Ethernet-кадры не имеют механизма TTL, который ограничивал бы количество переходов, широковещательные кадры могут циркулировать по сети бесконечно.

Это приводит к:

- Broadcast Storm — широковещательному шторму.
- MAC Address Flapping — постоянному перемещению MAC-адресов между портами.
- Duplicate Frames — появлению дублирующихся кадров.
- Перегрузке коммутаторов и каналов связи.

В результате сеть может стать практически недоступной.

## 3. Решение проблемы — STP

Для предотвращения L2-петель используется протокол Spanning Tree Protocol (STP).

STP был разработан Радьей Перлман (Radia Perlman) в компании Digital Equipment Corporation (DEC) в 1985 году. Позднее протокол был стандартизирован IEEE в стандарте IEEE 802.1D.

Основная задача STP — предотвращать петли второго уровня, сохраняя при этом резервные физические соединения.

Для этого STP логически блокирует некоторые избыточные порты. Если активный путь перестаёт работать, протокол может перевести резервный путь в состояние пересылки кадров.
