# STP (Spanning Tree Protocol) и проблема L2-петли

## 1. Что такое L2-петля?

Для начала разберёмся, что такое L2-петля.

L2-петля — это проблема, возникающая на канальном уровне модели OSI (Layer 2).

Когда мы соединяем несколько коммутаторов, они работают корректно. Но если для отказоустойчивости мы создаём между ними резервные физические соединения, может возникнуть проблема — **L2 Loop (петля второго уровня)**.

## 2. Как возникает L2-петля?

Представим, что у нас есть три коммутатора, соединённые между собой в форме треугольника. STP при этом отключён.

1. ПК отправляет широковещательный кадр (Broadcast).
2. Первый коммутатор получает кадр и отправляет его через все порты, кроме того, через который кадр поступил.
3. Второй коммутатор получает этот кадр и также рассылает его через остальные порты.
4. Третий коммутатор делает то же самое.
5. В результате кадр снова возвращается к первому коммутатору через другой порт.

Поскольку Ethernet-кадры не имеют механизма TTL, который ограничивал бы количество переходов, широковещательные кадры могут циркулировать по сети бесконечно.

Это приводит к:

- Broadcast Storm — широковещательному шторму.
- MAC Address Flapping — постоянному перемещению MAC-адресов между портами.
- Duplicate Frames — появлению дублирующихся кадров.
- Перегрузке коммутаторов и каналов связи.

В результате сеть может стать практически недоступной.

## 3. Решение проблемы — STP

Для предотвращения L2-петель используется протокол Spanning Tree Protocol (STP).

STP был разработан Радьей Перлман (Radia Perlman) в компании Digital Equipment Corporation (DEC) в 1985 году. Позднее протокол был стандартизирован IEEE в стандарте IEEE 802.1D.

Основная задача STP — предотвращать петли второго уровня, сохраняя при этом резервные физические соединения.

Для этого STP логически блокирует некоторые избыточные порты. Если активный путь перестаёт работать, протокол может перевести резервный путь в состояние пересылки кадров.

**Однако у классического STP есть существенный недостаток — скорость сходимости.**

При изменении топологии, например при обрыве активного соединения, восстановление связности может занимать примерно **30–50 секунд**. Для современных сетей такая задержка может быть критичной.

Чтобы решить эту проблему, был разработан **Rapid Spanning Tree Protocol (RSTP)** — усовершенствованная версия STP, стандартизированная в IEEE 802.1w.

RSTP значительно сокращает время восстановления сети после изменения топологии. Вместо ожидания длительных таймеров классического STP он использует более быстрый механизм согласования ролей и состояний портов.

В следующем разделе рассмотрим, как работает RSTP и чем он отличается от классического STP.






# RSTP — Rapid Spanning Tree Protocol

Как мы уже выяснили, классический STP может восстанавливать сеть после обрыва соединения примерно за 30–50 секунд. Для пользователей это означает, что в течение этого времени сеть может быть недоступна.

Чтобы уменьшить это время, появился RSTP (Rapid Spanning Tree Protocol).

Главное отличие RSTP от STP — скорость восстановления сети. RSTP быстрее реагирует на изменения топологии и быстрее переключает трафик на резервный путь.

Например, у нас есть три коммутатора, соединённые между собой. Один из портов не используется для передачи трафика, чтобы не образовалась петля. Если основной канал перестанет работать, RSTP сможет быстрее задействовать резервное соединение.

### Роли портов RSTP

У RSTP есть несколько ролей портов:

- **Root Port (корневой порт)** — порт, через который коммутатор имеет самый короткий путь к главному коммутатору (Root Bridge).
- **Designated Port (назначенный порт)** — порт, который отвечает за передачу трафика в определённом сегменте сети.
- **Alternate Port (резервный порт)** — запасной путь к главному коммутатору. В обычном состоянии не передаёт пользовательский трафик. Если основной путь перестанет работать, он может быстро включиться.
- **Backup Port (резервный порт)** — запасной порт для другого порта того же коммутатора в одном сетевом сегменте. В обычной сети встречается редко.

### Состояния портов RSTP

У RSTP есть три состояния:

- **Discarding** — порт не передаёт пользовательские кадры и не обучается MAC-адресам. Например, резервный порт Alternate обычно находится в этом состоянии.
- **Learning** — порт изучает MAC-адреса устройств, но пока не передаёт пользовательские кадры.
- **Forwarding** — порт передаёт пользовательские кадры и изучает MAC-адреса.

### Как это работает на практике?

Представим, что у нас есть основной путь между коммутаторами и резервный путь.

Пока основной путь работает, резервный порт Alternate находится в состоянии Discarding. Он не пропускает пользовательский трафик, чтобы не возникла петля.

Если основной путь перестанет работать, RSTP может быстро перевести резервный порт в состояние Forwarding.

Таким образом, резервное соединение начинает передавать трафик, и сеть восстанавливает связь быстрее, чем при классическом STP.

**Главная идея RSTP:** не просто блокировать лишние соединения, а держать резервный путь готовым к быстрому переключению.
